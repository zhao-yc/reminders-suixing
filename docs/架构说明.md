# 最小验证架构

本项目使用 uni-app Vue3；手机与桌面共用页面，iCloud 仍是数据的来源。没有自建业务后端，也不依赖常开 Mac。

## 分层

1. **共用页面**：只调用 `openSite`、`execute` 等固定接口，不感知 `plus` 或 Electron。
2. **平台桥接**：Windows 使用无原生权限的独立 Electron 网页容器；Android 使用 `plusrequire: none` 的独立 WebView。鸿蒙不能使用 `plus`，后续需使用 ArkWeb 或内置 WebView 的原生桥接能力实现同样协议。
3. **共用 DOM 适配器**：递归同源 iframe，识别清单和事项，通过当前网页实际暴露的记录 ID 操作，不调用私有网络接口。

## 固定命令协议

- `read`：读取清单及当前清单已加载的事项，并返回当前页面句柄。
- `selectList`：使用当前页面内的清单句柄切换清单；清单名称相同也不会混淆。
- `setCompleted`：提交明确的目标完成状态，同时携带页面句柄、清单句柄、真实记录 ID、读取时的状态和内容指纹。

事项 ID 来自网页，可能含账户相关标识，只在应用运行时使用，不进入公共测试数据或文档。清单句柄在页面重载后失效，不能持久化为云端 ID。

## 写入结果

网页控件需要完整的指针交互序列。调用单独的 `click()` 在真实 iCloud 中不一定生效，适配器对此有回归测试。

适配器先核对当前页面与内容，再提交一次交互。观察到网页状态更新时返回 `WEB_STATE_OBSERVED`，同时明确 `cloudConfirmed: false`。没有回执时返回 `UNCERTAIN_WRITE`，清除旧快照的写权限，不重新点击。

这避免在网络不稳定或重复提醒生成下一次事项时误重放操作。首版不自动补偿、不合并离线写入。

## Android 窗口与请求生命周期

`lib/android-bridge.js` 在 `APP-PLUS` 分支内实现原生容器；`lib/bridge.js` 只在该分支导入它和唯一适配器源文件。远程页面使用 `plusrequire: none`，按[HTML5+ 官方说明](https://www.html5plus.org/doc/zh_cn/webview.html)不注入 5+ API。

命令发出前先检查是否忙碌，再考虑创建或切换窗口。执行期间不允许切换区域、重新加载或派发另一命令，但可以显示同一官方窗口供使用者核对。加载、错误、关闭及超时均结束对应请求；若是写入，返回 `UNCERTAIN_WRITE`，不再派发。旧窗口事件、旧请求回执不能改变新窗口的就绪状态或解除读取要求。下一次更改必须先成功读取当前页面。

返回通道只接收当前窗口和请求匹配的固定结构；限制 URL 编码后的消息长度，避免中文正文扩大传输体积。超过范围时不拆分重发，不把网页回执提升为云端保存证据。合成测试覆盖这些事件顺序及共享适配器的实际读写，但原生事件触发顺序、URL 长度上限、隐藏窗口执行和登录仍必须在 Android 真机验证。

## 后续验证顺序

1. 独立 Windows 客户端登录、读取、完成、重载核对、应用重启后的会话保持。
2. Android 真机验证同一协议，重点检查官方登录、Cookie、URL 消息长度、隐藏 WebView 与返回导航。
3. 鸿蒙配置开发工具链，通过不依赖 `plus` 的桥接实现同一协议，再做真机验收。
4. 最后增加编辑、子任务、重复提醒、缓存及本地通知。
