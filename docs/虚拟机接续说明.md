## 在新电脑接续

- 克隆 [zhao-yc/reminders-suixing](https://github.com/zhao-yc/reminders-suixing)。Windows 代码从 main 的合入提交 61bc4a8 接续，包含 [PR #5](https://github.com/zhao-yc/reminders-suixing/pull/5)。本轮 Windows 实测记录在分支 codex/windows-acceptance-20261106。
- Android 单条删除改动在 codex/android-apk-20261105 和[草稿 PR #6](https://github.com/zhao-yc/reminders-suixing/pull/6)。这是单独的开发分支，接续前核对 GitHub 上的最新提交和 CI。
- 先读 AGENTS.md 和 [README](../README.md)。使用 Node.js 24 和 HBuilderX，原虚拟机使用 HBuilderX 5.34.2026102909。在新机器设置 HBX_CLI 指向实际 cli.exe，再用 scripts/hbx.ps1 发布 Web 或导出 Android 资源。预览继续使用 HBuilderX，Windows 真账号验收使用 Electron。
- 新机器通过官方页面重新认证。iCloud 会话、签名密钥及密码、安装产物和本地日志均留在原环境。若需要更新旧测试 APK，须用同一签名原件。使用新测试签名时在独立环境验证安装。原 Android 测试签名未完成用户指定的 E 盘备份。

## Windows 实测与接续点

- 原 Windows 0.1.3 安装版通过 2026-11-06 整机重启后的真实登录复用测试。验证前后为同一安装版与系统会话，启动后无需再次认证，定向读到专用清单四条。此安装版早于 PR #5。PR #5 的便携包单独通过真实前台导航读取，新安装器在启动 NSIS 编译器时失败。
- Mac/iPhone 原生新增已完成一次。专用清单“随行验证（2026-11-04）”中的“随行验证 · Windows 自动更新验证”仍保留，旧观察已明确结束。数轮自动读取未见新增，原官方页面手动定向读取也只见三条，重载后读到四条。修复后另起独立观察，避免重复创建已有同名事项或重放旧写操作。
- 当前自动更新只读官方网页已加载的当前清单。验证改进时分别记录旧窗口自动收到、主动重载读取、独立会话读回。保留选区、编辑草稿和中断后的只读保护。
- 新环境的构建、合成、真实页面、独立客户端和设备证据分别记录。测试只使用专用“随行验证”清单及事项，结果不确定时先读回核对。
